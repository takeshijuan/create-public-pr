# Contributing

Thanks for improving `create-public-pr`.

1. Open a focused issue or discussion for behavior changes.
2. Keep each pull request limited to one public-safe concern.
3. Add or update tests before implementation changes.
4. Use only Python standard-library modules in runtime code.
5. Run the repository checks documented in the README.
6. Use a repository-local GitHub noreply identity and follow the skill's privacy gates.

Do not include credentials, private links, internal trackers, local paths, personal addresses, or proprietary context in issues, fixtures, commits, or pull requests. Construct security-test signatures from harmless fragments.
